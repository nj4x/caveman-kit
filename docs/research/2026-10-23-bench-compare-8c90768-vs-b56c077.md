# Bench comparison: agentic 8c90768 vs b56c077 (Context Diet)

Date: 2026-10-23

This note compares two agentic benchmark runs of the Context Diet gate (ADR 0008 decision 8, ADR 0009). It builds on the two per-run notes and does not repeat their tables:

- `docs/research/2026-10-13-bench-agentic-claude-sonnet-5-5-8c90768.md` (run 1, includes the maintainer's merge override)
- `docs/research/2026-10-21-bench-agentic-claude-sonnet-5-5-b56c077.md` (run 2, untracked at the time of writing)

Shorthand used below:

- R1 = `bench/results/agentic-claude-sonnet-5-5-8c90768/`
- R2 = `bench/results/agentic-claude-sonnet-5-5-b56c077/`

Every number below was recomputed from the 144 cell files (`<arm>--<fixture>--s<seed>.json`) and 144 stream files (`*.stream.jsonl`) in R1 and R2. Cost is the harness's cache-weighted input cost, `input + 0.1 x cache_read + 1.25 x cache_creation` tokens (`bench/lib/stats.js`, `cacheWeightedCost`). Paired intervals are 95% t-intervals computed with `bench/lib/stats.js` `tCritical95`. The headline gate figures in both per-run notes were reproduced exactly (R1: diff -3710.7, CI [-8985.1, +1563.6]; R2: diff +2702.7, CI [-1600.2, +7005.6]). No `node bench/run.js` call was made.

## Bottom line

1. The two runs used the same configuration. The model, CLI version, fixtures, arms, hooks and injected SessionStart text are identical (see "Configuration"). So R2 is a replication of R1, run 8 days later, not a test of a changed kit.
2. The gate result flipped sign between the replications. R1 had full-diet 9% cheaper than full; R2 had it 7% more expensive. Both intervals include zero, so both runs give `no-ship`. The swing itself is within noise.
3. Pooling both runs (48 pairs) gives a paired cost difference of -504 tokens, 95% CI [-3910, +2902]. This is about -1.3% of the full arm's mean. The data show no cost effect from Context Diet, in either direction, at this sample size.
4. One effect replicates: full-diet reads less via the `Read` tool than full in both runs. This does not turn into lower cost.
5. R2 contradicts two of the three diagnostics the maintainer cited when overriding the R1 verdict (turns and output). It agrees on `read_chars`.

## Configuration: what differs and what does not

**Hooks.** `git diff 8c90768 b56c077 -- hooks/` is empty. The only kit-code change between the two commits is the skill pin in `install.sh` (`JuliusBrussee/caveman@v3.2.0` to `@v4.0.1`, commit `f14f5f7`), plus `CLAUDE.md` text.

**Injected context.** The SessionStart `hook_response` output was hashed for every cell in R1 and R2. Each arm has exactly one distinct value across all 144 cells:

| Arm | Injected chars | SHA-1 prefix | Same in R1 and R2 |
| --- | --- | --- | --- |
| bare | 0 | da39a3ee (empty) | yes |
| full | 4670 | 5e6d38be | yes |
| full-diet | 5004 | 43f70dbb | yes |

The models saw byte-identical rulesets in both runs. So the `install.sh` skill-pin change does not confound the comparison: the bench copies `SKILL.md` from the installed skill (`bench/README.md`, "Isolation and auth"), and the filtered result was the same. The Context Diet supplement adds 334 characters (5004 - 4670). Only `SessionStart:startup` fired, 144 times per run (stream `hook_name` field). No SubagentStart hook fired in any cell.

**Harness.** Commit `8c90768` does not contain `bench/`. R1 was run from this checkout's `bench-harness` branch, with `--kit-dir` set to the context-diet worktree. `git diff --stat 17872bd b56c077` lists no `bench/` files, so the committed harness that recorded the R1 evidence is the same as the harness at `b56c077`. Uncommitted harness state at R1 time cannot be checked from the repo. The cell schema is identical in both runs.

**Environment.** Wall-clock time per cell was longer in R2 for every arm. Mean `durationMs` for bare/full/full-diet was 97.3/103.0/92.1 s in R1 and 140.2/119.1/113.4 s in R2. This points to API latency or machine load. Duration is not part of any metric.

## Is the difference meaningful?

The two runs used the same configuration, so pooling them into 48 pairs is a fair estimate of the Context Diet effect for this setup. Pooled results (R1 and R2 cell files):

| Metric (full-diet - full) | Pooled mean | 95% CI |
| --- | --- | --- |
| cost | -504 | [-3910, +2902] |
| output tokens | +23 | [-121, +167] |
| turns | -0.2 | [-0.9, +0.5] |
| Read chars | -1334 | [-2787, +119] |
| USD | -0.0008 | [-0.0078, +0.0062] |

This is not the gate procedure in ADR 0008. The gate is defined per run, with escalation to 6 seeds at most once. The pooled figure is reported as evidence only. It shows a cost effect close to zero, with an interval of about +/-8.5% of the full arm's mean cost. This is consistent with both per-run verdicts (`no-ship`). It also means that a real effect much smaller than about 3.5k tokens per task cannot be detected at this N. The between-cell cost SD within one arm is 9k to 12k tokens (table above).

Read chars point the same way in both runs: the full-diet arm read 16% less than full in R1 (139903 to 117173) and 27% less in R2 (152570 to 111269). The per-run notes report these totals, and the cell `diagnostics.readChars` fields reproduce them. This is the only diet-related signal that replicates. It does not show up in cost.

A likely reason (an inference, not measured directly): the average per-cell Read saving is about 1.3k characters. That is roughly a few hundred tokens, re-sent at the 0.1 cache-read weight. By contrast, cache_write and cache_read per cell vary by thousands of tokens between seeds, mostly with turn count and output (arm table above). The supplement also adds 334 characters of fixed context to every full-diet session.

Caveman `full` mode itself reduced output tokens by about 230 per task against bare in both runs (-12.5% in R1, -12.5% in R2, see the full - bare row). The interval excludes zero only in R2. Cost did not move in either run.

## Agreement with the existing notes

Where R2 agrees with the R1 note (`docs/research/2026-10-13-bench-agentic-claude-sonnet-5-5-8c90768.md`):

- Verdict `no-ship`, because the cost interval includes zero after escalation.
- Pass rate 24/24 in every arm, no turn-capped cells, no re-reads.
- `read_chars` drops from full to full-diet.

Where R2 disagrees with the R1 note's "Decision" section:

- The R1 note says "the diagnostics point the right way" and cites `turns` 202 to 186. In R2, turns went from 199 to 206 (full to full-diet). The pooled turn difference is -0.2 [-0.9, +0.5].
- The R1 note cites output as roughly flat (38844 to 38694). R2 shows 39940 to 41198. Neither change is significant.
- The R1 point estimate (-3711, a 9% saving) did not replicate. R2's point estimate is +2703.

The R2 note (`docs/research/2026-10-21-bench-agentic-claude-sonnet-5-5-b56c077.md`) reports the gate and diagnostic tables only. It has no Decision section, and it does not mention that the run measures the already-merged hooks (ADR 0009 requires the gate to pass before a merge). The R1 note links follow-up issue #11 for analyzing the missing cost effect. The pooled data above are direct input for that issue.

## Caveats

- **Routing contamination (found 2026-10-24).** The run went through anthproxy `127.0.0.1:8083` with auto model routing on, so the requested model was rewritten per request. The proxy log shows bench requests on opus and sonnet: about 58% opus and 42% sonnet, and 9 of 24 gate pairs compared different models. The stream files still report `claude-sonnet-5-5`. This run does not measure the model the gate names; see ADR 0011 and `bench/README.md`, "Routing proxy". R1 (8c90768) is not in the proxy DB, so its routing is unknown.

- **Redaction corrupts stored text.** `bench/lib/agentic.js` redacts by `text.split(ANTHROPIC_API_KEY)`. In both runs the key value was short enough to match ordinary digit sequences, for example line numbers in `model_router.py` (`[redacted]3`, `\n[redacted]0\t`). `[redacted]` appears 326 times in R1 and 321 times in R2, in 77 and 80 of 144 files. That includes some cell `result` and `hiddenTest.tail` fields and one stream UUID in R2. The `diagnostics` are computed from the unredacted stream before redaction (comment in `bench/lib/agentic.js`), and `usage` is numeric, so no metric above is affected. Re-deriving diagnostics from the stored `.stream.jsonl` files would give slightly different numbers. The pattern also leaks partial information about the key's shape. Consider a minimum-length guard before redacting.
- **Ceiling on quality.** Every cell passed, so the hidden-test guardrail has no power on these four fixtures. A quality regression from the diet would not be visible.
- **Different days.** R1 and R2 ran 8 days apart, and latency differed (duration means above). The configuration is identical, but backend-side changes cannot be ruled out from the files.
- **Kit-dir path differs.** R1 measured a worktree, R2 the main checkout. The hooks diff is empty and the injected text is byte-identical, so this affects only the path in the per-run note, not the measurement. Neither note marks its commit `-dirty`.
- **No SubagentStart coverage.** No SubagentStart hook fired in any cell, so the SubagentStart half of ADR 0009 decision 2 is not exercised by these fixtures.
- **Pooling is outside the gate.** The 48-pair figures are evidence, not a gate verdict under ADR 0008.
